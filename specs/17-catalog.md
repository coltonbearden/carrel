# spec: catalog — index durability and portability

**Owns:** `src/carrel/core/db.py`, new `src/carrel/commands/catalog.py`, `src/carrel/cli.py` (register `"catalog": "catalog"` in `COMMANDS`), `src/carrel/commands/index.py` (add `--status`; may extract a public `index_paths(...)` for spec 15 to reuse), new `tests/test_catalog.py`, `docs/ARCHITECTURE.md` (one drift fix, below).
**Wave:** 2 (spec 19 edits `cli.py` in wave 1; do not run concurrently).

## Why
`.carrel/carrel.db` has no schema version, so the schema can never change safely. Tags and notes are the only data in the desk that cannot be regenerated by re-running `index`, and there is no way to export them, move a desk between machines, or commit them alongside a repo.

## db.py
- `PRAGMA user_version` drives an ordered `MIGRATIONS: list[tuple[int, str]]`. Version 1 = today's `_SCHEMA` exactly (a fresh DB is created at 1). `__enter__` applies every migration above the current version inside one transaction, then sets `user_version`. A DB at version 0 (pre-v0.2.0) is recognised as version-1 layout and stamped 1 without changes.
- `DeskDB.schema_version() -> int`; `DeskDB.counts() -> dict` (files, docs, tags, notes); `DeskDB.stale() -> dict` with lists `changed` (size/mtime differ, reuse `is_fresh`), `missing` (path gone), plus `unindexed_count` computed by the caller from a walk.
- Export/import helpers: `export_catalog() -> dict`, `import_catalog(data, *, replace: bool) -> dict[str, int]` (tags/notes added, files touched). Import creates `files` rows with `ensure_file` when the file exists on disk; entries whose file is missing are counted under `skipped_missing` and not imported.
- Adding a migration is now the only sanctioned way to change the schema — say so in the module docstring.

## CLI
```
carrel catalog export [-o FILE]            # default stdout; JSON
carrel catalog import FILE [--replace]
carrel catalog status [--json]
carrel index --status                      # alias of `catalog status`
```
- **export** — `{"schema": 1, "product": "<cli>", "version": "<version>", "exported": "<iso>", "root": "<abs root>", "files": [{"path": "<root-relative>", "tags": [...sorted], "notes": [{"created": <float>, "body": "..."}]}]}`. Only files with ≥1 tag or note; sorted by path; deterministic (byte-identical across runs when nothing changed, apart from `exported`). `-o` refuses to overwrite without `--force`.
- **import** — merge by default: tags `INSERT OR IGNORE`; notes deduplicated on `(file_id, created, body)`. `--replace` deletes all tags and notes first (asks nothing — it is scriptable — but prints what it removed). Exits 4 on unreadable/invalid JSON or `schema` newer than supported. `--json` reports `{tags_added, notes_added, files_touched, skipped_missing}`.
- **status** — `{schema_version, db_path, counts: {files, docs, tags, notes}, stale: {changed: N, missing: N, unindexed: N}, examples: {changed: [≤5 paths], missing: [≤5], unindexed: [≤5]}}`; human view is a small table with a one-line hint (`run carrel index` / `carrel index --prune`) when anything is stale. Exit 0 always (it is a report); exit 4 if no `.carrel` under root.
- All three take the global `--root` and `--json` like every db command.

## Acceptance
- Round trip: index fixtures in a tmp root, add 2 tags + 1 note to two files, `catalog export -o desk.json`, delete `.carrel/`, `index` again, `catalog import desk.json` → `tag ls` and `note ls --json` for both files equal their pre-export output; a second import reports `tags_added == 0 and notes_added == 0`.
- `--replace` after adding an extra tag removes it and restores exactly the exported set.
- Import with a `files[]` entry whose path does not exist → `skipped_missing == 1`, exit 0.
- Invalid JSON and `schema: 99` → exit 4 with a message.
- Fresh DB: `schema_version() == 1`. A DB created by executing the v0.1.2 `_SCHEMA` string with `user_version = 0` opens and reports version 1 afterwards, data intact.
- `catalog status --json` after modifying one indexed file and deleting another: `stale.changed == 1`, `stale.missing == 1`; `index --status` prints the same payload.
- `carrel catalog --help` and each subcommand's `--help` work; every subcommand accepts `--json`.
